# Xiaohongshu (RED) Image-Note Auto Publisher — Vision + Keyboard Automation (Headless-capable)

No web backend, no CDP, no JS injection. Pure **OCR + real mouse/keyboard events** to drive the
Xiaohongshu Creator Platform and publish image-text notes automatically. **Verified working in a
display-less environment (Xvfb virtual screen).**

```
wmctrl find window → import screenshot → PaddleOCR recognize text → coordinate mapping → xdotool click/type
```

## Features

- One-shot publish: upload cover → quote another note → AI-written title/body → hashtags → @account → publish
- Title/body generated by any LLM (OpenAI-compatible endpoint; endpoint/model/API key all via env vars), cached to disk, editable by hand
- Every step has a deterministic pass criterion; on failure it stops (prints live OCR + screenshot path), never guesses or retries blindly
- Step-by-step debugging: `--step 1/2/3/456/7`, one step at a time
- Headless mode: Xvfb `:99` virtual screen + openbox, no physical display needed

## Quick start

Dependencies: Linux + X11 (`wmctrl`, `xwininfo`, `xdotool`, ImageMagick `import`, `xclip`) +
Chrome + Python venv (paddleocr + numpy + PIL) + fcitx (optional in headless, auto-ignored).

```bash
PY=/path/to/venv/bin/python
S=/path/to/xhs_manual_publish.py

# Required env (the script stores no keys itself)
export XHS_API_KEY=your_llm_key          # AI writes title/body
export XHS_LLM_BASE=https://your-endpoint/v1
export XHS_LLM_MODEL=your-model

# Step by step (one step at a time, each with pass criteria)
DISPLAY=:0 $PY $S --step 1 --image cover.png
DISPLAY=:0 $PY $S --step 2 --quote "https://www.xiaohongshu.com/explore/..."
DISPLAY=:0 $PY $S --step 3                  # no title given → AI writes one
DISPLAY=:0 $PY $S --step 456 --topics "#topic1 #topic2 ..." --at "account_name"
DISPLAY=:0 $PY $S --step 7                  # really publish
# --no-publish stop before publishing / --regen regenerate copy / --spec other spec file
```

The spec file (default `2说明` next to the script, override with `XHS_SPEC`) holds the copy
requirements: title brief, body brief, hashtags, @account, quote link.

## Headless (no display) publish

```bash
Xvfb :99 -screen 0 2560x1440x24 &      # resolution must match physical screen
DISPLAY=:99 openbox &                  # a window manager is required
# Chrome with a separate profile (rsync from the logged-in profile, excluding Cache/Singleton)
env DISPLAY=:99 google-chrome --user-data-dir=~/.config/google-chrome-xvfb --new-window --no-first-run \
  "https://creator.xiaohongshu.com/publish/publish?source=toolbar"
export DISPLAY=:99
bash scripts/开始发布.sh --no-publish   # dry run
bash scripts/开始发布.sh                # real publish
```

Headless-specific pitfalls (already fixed in the script):
1. **The file dialog pops up on the physical screen `:0`** (Chrome uses GTK portal, which connects
   to the system session bus) → `find_dialog()` searches both displays for the "Open File" window
   and operates it with the right `DISPLAY`
2. **Hardcoded scan regions break on smaller windows** (the "Confirm quote" and "Publish" regions
   were desktop-sized) → widened / dynamically taken from the bottom of the window
3. **Don't switch to a private dbus session** (no keyring → cookies can't be decrypted) → always
   use the system session bus

## Layout

| Path | What |
|---|---|
| `xhs_manual_publish.py` | Main orchestrator (publish pipeline + AI copy + pass criteria) |
| `ui_ocr_click.py` | Low-level library: window lookup / screenshot / OCR / coords / click / dismiss dialog |
| `scripts/开始发布.sh` | One-click launcher (pre-checks → parse spec → run pipeline → log) |

## Configuration (all via env vars, no hardcoding)

| Variable | Purpose | Default |
|---|---|---|
| `XHS_API_KEY` | LLM API key (required) | none |
| `XHS_LLM_BASE` | OpenAI-compatible LLM endpoint | `https://your-llm-endpoint/v1` |
| `XHS_LLM_MODEL` | Model name | `your-model` |
| `XHS_SPEC` | Spec file path | `2说明` next to the script |
| `XHS_LOG_DIR` | Log directory | `./logs` |
| `XHS_PY` / `XHS_SCRIPT` / `XHS_DIR` | Launcher's interpreter / script / workdir | relative to script |

## Key design decisions

- No web backend: CDP can be detected by the page (`navigator.webdriver`, ...) and synthesized DOM
  events carry `isTrusted=false`. This pipeline works from the screen-pixel side; events go through
  the X11 input pipeline (XTest), the same path as a real human
- Coordinates are measured live, never hardcoded (window origin changes every run); OCR drops the
  first character, so validation uses "any 5-char substring match"
- XHS buttons give no hover/press feedback → always `--no-verify`, real validation is "did the page change"
- Publish success criterion: URL contains `published=true` (not `publish/success`)

## Security

- No API keys / tokens / passwords / account info / business content in this repo: the LLM key is
  read only from environment variables
- No OCR model files (PaddleOCR models are downloaded automatically by the venv on first run)
- No user data (publish logs, Chrome profile, caches)

## Known limitations

- X11 / Xvfb only; on Wayland switch to `grim` + `ydotool`
- Depends on a logged-in Chrome profile; re-tune the criteria when the site layout changes
